# 지역별 게임 데이터 업데이트 점검

일본판 16.0 업데이트 대비 지침이다. 현재 로컬 세일 화면은 한국판·일본판 15.7 원본으로 작성했으며, 이 지침을 추가하면서 16.0 업데이트나 원격 배포를 실행하지 않았다.

## 한국판 데이터와 이미지 보호

- 일본판 업데이트는 `regions.jp`의 버전·원본 해시·풀·보상 정의를 갱신한다. `regions.kr`의 기존 데이터와 한국어 이름을 일본어로 덮어쓰지 않는다.
- 이미지 우선순위는 **이미 존재하는 사이트 파일 → 한국판 원본 → 일본판 원본**이다. 같은 파일명이 있으면 원본 언어와 관계없이 교체하지 않는다. 일본판에만 새로 생긴 파일은 새 경로로 추가할 수 있다.
- `.github/scripts/build_sale_catalog.py`의 `copy_missing_assets({"kr": kr_dir, "jp": jp_dir}, destination)`은 이 순서를 강제하고 기존 파일을 건너뛴다. 파일 수가 많은 폴더를 통째로 덮어쓰는 동기화는 사용하지 않는다.
- `/img/sale`, `/img/bnr`, `/img/u`, `/img/r`, `/img/icon`, `/img/medal`, `/img/ui/gnb`의 변경 전 경로·해시를 기록한다. 기존 한국판 파일의 변경·삭제가 0인지 전체 비교한다. 임의 합성·재도색·가격 재작성은 하지 않는다.

## 새 항목과 로직 갱신

1. **가챠:** 지역별 `GatyaData_Option_SetR/N/E.tsv`, `GatyaDataSetR/N/E*.csv`, 특별 아이템 정의와 유닛·아이템 메타데이터를 함께 대조한다. `.github/gacha-catalog.json`에 새로운 ID·풀·이미지 연결·특별 보상 구조를 갱신한다. 일정만 갱신하면 새 풀은 지원되지 않는다.
2. **팩:** `itemPack.tsv`의 신규 server ID, 활성 여부, 상품별 구성품·수량과 조건 필드를 확인한다. `QuantityN` 열은 동적으로 읽지만, 새로운 보상 분류나 조건 의미는 원본을 확인한 뒤 처리 로직을 추가한다. 지역별 구성이 다르면 각각 보존한다.
3. **로그인 스탬프:** `DailyLoginEventData.csv`, `DailyLoginEventGrade.json`, `DailyLoginEventText_*`를 함께 확인한다. 현재 구조는 7개 헤더 뒤에 `보상 수, 표시 ID, (분류, ID, 수량) × 보상 수`가 일차별로 반복된다. 새 헤더·보상 종류·선택 조건이 추가되면 파서를 먼저 수정한다. 일차를 실제 달력 날짜나 플레이어의 출석 진행도로 임의 환산하지 않는다.
4. **기타 보상:** `item.tsv`의 새로운 지급 ID가 있으면 게임 아이템과 연결을 확인하고 `update_sale_schedule.py`의 지급 ID 매핑을 갱신한다. 알 수 없는 팩·스탬프·보상을 조용히 누락하지 않는다. 현재 수집기는 미등록 항목을 만나면 해당 세일 피드의 이전 유효본을 보존한다.
5. **이름과 색상:** 모든 표시명은 냥코DB 한국어 메타데이터 우선, 없을 때만 일본어다. `event/gacha-assets.json`의 `localizedNames`와 `bannerNames`도 새 카탈로그에 맞춰 갱신한다. 지역별 이미지가 없는 가챠도 기존 정규 이름으로 테마를 찾는지 확인한다. 원본 `event.name`을 표시명으로 무조건 덮어써 기존 일정 덮어쓰기 그룹을 바꾸지 않는다.
6. **미션:** `Mission_Data.csv`, `Mission_Name.csv`, `Mission_Condition.csv`, `Mission_Unlock_Condition.csv`, `Mission_Group.csv`, `Mission_Monthly.csv`를 함께 대조하고 `.github/scripts/build_mission_catalog.py`로 `.github/mission-catalog.json`을 갱신한다. 한국어 이름 우선·지역별 목표 횟수/보수는 각 원본을 유지한다. 8000~9999의 주간·기간 한정 서버 일정만 표시한다. 컴백 미션의 원본 ID 9599~9606은 사용자 요청으로 수집·화면에서 제외하며 이전 피드에도 같은 제외를 적용한다. 버전 업데이트 시 새 컴백 미션 ID도 원본 이름·해방 조건으로 확인한다. 상시 미션(15000~15999, 사용자가 말한 메인 미션)과 월간 미션(17000~17999)은 사용자 요청으로 수집·달력·목록·설정에서 제외한다. 묶음 이름을 인용구에서 새로 만들지 않고 첫 미션의 원본 문구를 제목으로 사용한다. 신규 미션의 이름/보수를 확보하지 못하면 `unmapped`에 ID·최소 버전을 남기고 보수를 만들지 않는다. 현재 일본판 16.0용 9792·9802가 이 경우다.
7. **메달:** `medallist.json`, `medalname.tsv`, 실제 `medal_NNN.png`의 추가 ID·아이콘 수를 함께 확인한다. 빌더는 메달 정의/이름 수·원본 해시와 누락 이미지 ID를 카탈로그에 기록한다. `/img/medal`의 기존 한국판 이미지가 일본판 갱신으로 교체되지 않게 한다. 현재 추가된 000~126, 127개를 미션과 함께 다음 배포에 포함한다. 메달과 미션 보상 분류를 혼동하지 않는다. 현재 `Mission_Data.csv`의 보상 분류 4는 맵 해방이며 메달 지급이 아니다.
8. **버전:** 인증용 `REGIONS`와 실제 원본 버전을 구분한다. 미래 일정의 최소/최대 버전을 인증 버전으로 잘라내지 않는다. 일본판 16.0 원본이 들어와도 한국판 버전을 함께 올리지 않는다. 공유 리더의 인증 버전·국가 변경은 실제 접속 검증 후 결정한다.

## 세일 카탈로그 재생성

아래 명령은 기존 이미지를 수정하지 않는다. 경로는 실제 지역별 원본으로 지정한다.

```powershell
python -B .github/scripts/build_sale_catalog.py `
  --kr-root "<한국판 원본 폴더>" `
  --jp-root "<일본판 원본 폴더>" `
  --gacha-catalog .github/gacha-catalog.json `
  --labels .github/sale-labels.json `
  --assets img/sale `
  --output .github/sale-catalog.json
```

공통 팩 묶음명·한국어 보조 이름은 `.github/sale-labels.json`에 있고, 실제 상품별 한국어 명칭과 구성은 게임 원본을 우선한다. 새 이름은 한국판 원본이나 확인된 번역 근거를 사용한다.

공식 `item.tsv`를 확보한 뒤 `update_sale_schedule.py --region kr/jp --source-file ... --output ...`으로 각 지역 피드를 만든다. 일본판을 만들 때는 가능하면 `--korean-source-file`도 지정한다. 원본을 읽은 실제 시각을 유지하고, 오래된 파일을 다시 묶었다는 이유로 조회 시각을 최신으로 바꾸지 않는다. 두 피드를 `{"schemaVersion":1,"regions":{"kr":<KR 피드>,"jp":<JP 피드>}}`로 묶어 로컬 초기 스냅샷 `event/sale-data.json`도 갱신한다.

## 수집·검증·배포

- 준비된 워크플로는 기존 직렬 인증 순서를 유지한다. 가챠 수집기의 `--item-source-output`으로 이미 받은 `item.tsv`를 임시 보관하고 세일 수집기에 재사용한다. 세일 때문에 추가 인증 요청을 만들지 않는다.
- 여덟 피드 `stage/gacha/sale/mission-schedule-kr/jp.json`의 성공 여부를 따로 확인한다. 미션은 스테이지 수집기의 `--source-output` 원본을 재사용해 인증 요청을 늘리지 않는다. 스테이지 피드의 실제 `fetchedAt`을 그대로 전달한다. 발행기는 해당 JSON 한 개만 바꿔 다른 지역·종류의 파일을 보존한다.
- 가챠 풀·등급 확률 합계·확정 슬롯, 팩 구성·수량, 로그인 일차별 묶음, 반복 지급일, 날짜·버전 조건을 전체 비교한다. 새 메타데이터가 없을 때 갱신을 거부하고 이전 피드를 보존하는 경로도 확인한다.
- UI는 한국판/일본판, 320/390/1280px, 종류 필터·상시 포함·초기화·저장 복원, 월 경계·5줄/+N·일정 개수, 일차별 보상·툴팁·아이콘·접기, 메뉴 중복과 내부 스크롤을 독립 검토한다.
- 이번 세일 작업은 로컬 확인 단계다. 사용자에게 커밋·배포 요청을 받기 전에는 워크플로 실행·업로드·배포를 하지 않는다.

## 미션 카탈로그와 로컬 스냅샷

```powershell
python -B .github/scripts/build_mission_catalog.py `
  --kr-root "<한국판 데이터 폴더>" --jp-root "<일본판 데이터 폴더>" `
  --gacha-catalog .github/gacha-catalog.json --site . --output .github/mission-catalog.json
python -B .github/scripts/update_mission_schedule.py --region kr `
  --source-file "<스테이지와 같은 sale.tsv>" --fetched-at "<실제 조회 시각>" --output "<지역별 미션 JSON>"
```

지역별 미션 JSON을 `event/mission-data.json`의 `regions.kr/jp`에 묶는다. 원본 전체 유효기간에서 반복 구간을 확장하며 선택 월/주별로 배치나 날짜를 재설정하지 않는다. 미션 UI는 `sale.js`의 동일 달력/보상 렌더러를 사용한다. 설정의 진행도 체크박스는 기본 체크이며 저장·복원·초기화한다. 주간 미션만 원본 해방 조건 15(세계편 1장 달 이후, 3장 달 이전)와 11(세계편 3장 달 이후) 중 진행도에 맞는 목표·보수를 표시한다. 같은 `【제목】`은 원본 일정이 달라도 제목으로 묶되, 각 목표의 실제 유효 구간은 그대로 유지한다. 사용자가 지정한 월별 12개 시리즈의 36개 원본 미션 ID는 ‘럭키 티켓 G’, 풍운·이계 냥코탑 30·40·50층의 6개 ID는 ‘냥코탑’으로 묶는다. 그 외 미분류 묶음은 모든 목표가 동일한 `「제목」`으로 시작할 때 그 안의 문구를 묶음 제목으로 사용한다. 일부만 일치하거나 시작 부분이 아니면 적용하지 않는다. 나머지 제목 없는 묶음은 ‘미션 묶음’, 주간은 원본 주차의 8008/8009에 따라 ‘주간 미션(개다래)’/‘주간 미션(레전드)’다. 여러 목표 묶음은 세일과 같은 접기·펼치기를 사용하며 처음에는 접힌 상태다. 목표가 하나뿐이면 묶음 제목이나 접기·펼치기 없이 원래 목표와 보수를 표시한다. 모든 미션 목표는 같은 h3·기간·보상 구조를 사용하며 첫 목표만 다른 제목/이미지로 렌더링하지 않는다. 목표와 기간은 각 행 왼쪽, 보수는 맨 오른쪽에 배치하며 기존 아이콘 크기·툴팁·×1 수량 표시는 유지한다. 제목 옆 미션 이미지는 표시하지 않고 GNB와 보수 이미지는 유지한다. 단, 설정 패널의 기존 접기/펼치기는 유지한다. 새 UI 검증은 4개 탭, Safari 가로·세로 및 숨김 회전의 공통 프레임 크기까지 포함한다. 현재 작업은 로컬 구현이며 이후 명시적인 커밋·배포 요청까지 업로드하지 않는다.

미션 카탈로그 빌더는 `build_mission_targets.py`로 `event/mission-targets.js`도 함께 생성한다. 원본 조건 0의 맵 ID, 조건 1의 개별 스테이지 코드, 조건 24의 `Mission_LimitOption.json` 내 Map/Stage를 기존 DB 페이지에 연결한다. 한국어 우선 카탈로그 명칭을 사용하며 목록 중 일부라도 DB 대상이 없으면 불완전한 목록을 표시하지 않고 `unresolved`에 남긴다. 분류형(조건 20), 컬렉션·스코어 등 아직 확인하지 않은 인코딩은 추정 연결하지 않는다. APK 분석은 보류한다. 대상이 확인된 목표의 오른쪽 [?] 버튼은 기존 팝오버/툴팁 및 체크 컨트롤 스타일을 재사용하는 클릭형 도움창을 열고, 목록 링크는 이벤트 프레임 밖의 해당 스테이지 페이지로 이동한다. 닫기·Escape·바깥 클릭과 날짜/설정 변경 시 닫기를 지원한다.

대상 스테이지 도움창의 링크는 스테이지 제목 옆 위치 URL과 같은 `a.map-name` DOM·스타일을 사용한다. [?] 버튼은 보수 왼쪽에 두고, 보수 오른쪽 여백과 좌표는 도움 버튼이 없던 배치 그대로 유지한다. 이차원 콜로세움의 조건 30은 현재 연결 범위에 추가하지 않고 읽기 전용 조사 대상으로 남긴다.

## 메달·냥콤보 공용 검색 갱신

메달 카탈로그(`medal/catalog.json`)와 냥콤보 데이터(`unit/nyancombo-data.js`)를 갱신한 뒤 아래 명령으로 공용 검색의 추가 목록을 갱신한다. 기존 유닛·적·아이템·스테이지 목록과 진화 재료 매핑은 재생성하지 않고 그대로 보존한다. 한국어 우선 이름은 각 원본 카탈로그의 값을 사용한다.

```powershell
python -B tools/search_catalog_extras.py --site .
```

공용 검색의 `medals`와 `combos`에는 이름·원본 ID·아이콘·목록 내 항목 링크만 기록한다. 메달은 기존 개별 아이콘을 사용하고, 냥콤보는 GNB 원본을 변경 없이 복사한 `img/icon/combo.png`를 사용한다. 전체 검색 카탈로그 생성기 역시 동일한 추가 목록 빌더를 호출한다. 원본 메달·냥콤보 데이터가 없거나 형식이 잘못되면 부분 갱신 명령은 기존 검색 파일을 덮어쓰지 않는다.
