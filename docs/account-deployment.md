# 로그인·마이페이지 운영 배포

이번 배포는 기존 공개 로그인 폼에 로컬에서 사용하던 서버와 마이페이지를 연결한다. 로그인 성공 후 `/mypage/`로 이동하며, 회원가입 링크와 `/mypage/signup.html`은 기존 공사중 애니메이션 화면을 사용한다. Google/이메일 가입 기능은 활성화하지 않는다.

기존 UI를 새로 구현하지 않고 마이페이지 HTML·CSS·JS와 공개 메타데이터·패시브 이미지를 선별 복사한다. 공용 stage-list의 선택/장식 옵션과 stage-filters의 AbortSignal 지원은 기존 로컬 구현을 가져오며 옵션을 지정하지 않은 다른 페이지의 동작은 유지한다. 로그인 POST는 기존 bootstrap 요청의 완료를 기다려 처음 방문할 때 CSRF 쿠키와 경쟁하지 않게 한다.

서버는 기존 Supabase Auth 검증, 고유 아이디 조회, 암호화된 계정 Storage 조회/저장, 연동/수동 편집 정책을 재사용한다. 신규 파서는 도입하지 않는다. 서버 함수가 공개 이미지와 전체 스테이지 HTML을 포함하지 않도록 별도 bundle 제외 규칙을 두고, 기존 HTML 평가 함수로 만든 장·성급 검증 규칙만 포함한다. 이 스냅샷은 카탈로그/스테이지 생성 뒤 `python -B account_service/build_stage_rules.py --site .`로 갱신한다.

운영 환경은 `Project team / nyankodb`, 정식 출처는 `https://nyanko.wiki`다. `www.nyanko.wiki`는 정식 출처로 이동시켜 로그인과 CSRF가 같은 출처를 사용한다. 필요한 다섯 설정은 사용자 승인 후 Production Secret으로만 등록했다. 키 값은 소스·정적 JS·보고서·테스트 출력에 넣지 않았다. 업로드용 임시 파일도 등록 후 삭제했다. 로컬 비공개 설정과 시험 계정은 기존 위치에 보존한다.

검증은 실제 Supabase 시험 계정의 로그인·서버 세션 확인·기존 암호화 계정 조회·로그아웃과 기존 서버 계약 테스트 61개를 포함한다. 기존 계약 테스트의 비공개 원본 fixture는 기존 폴더에서 읽었고 저장소/배포에 복사하지 않았다. UI fixture 검증은 실제 인증 확인과 구분해 별도 보고서에 남긴다. 계정 수정·게임 데이터 재수신을 실제 계정에 자동 실행하지 않는다.

배포 전 독립 UI 검사에서 bootstrap 대기 뒤 `event.currentTarget`이 사라져 정상 로그인 POST가 누락되는 문제를 발견했다. 이벤트가 유효한 동기 구간에서 form 참조를 보존하고 같은 FormData/POST 경로를 사용하도록 수정했다. 이는 미배포 시험 구현에서 발견·수정한 사항이며 운영 장애로 단정하지 않는다.

마이페이지가 사용하는 기존 `NyankoAccountDefaults` 본체와 인증 해제 시 clear, 하단 마이페이지의 실제 경로를 공용 GNB에 함께 반영했다. 단순 빈 함수로 대체하지 않았다. 로컬 공용 파일 전체를 덮어쓰면 기존 운영 analytics 로더가 삭제되는 차이를 독립 검사에서 발견하여, 원본 계정 모듈만 선별 결합하고 운영 analytics 로더는 그대로 보존했다. 기본 계정 적용 snapshot이 없으면 기존 계산기 설정/UI를 바꾸지 않으며 계정 적용·해제는 기존 코드의 명시적 사용자 조작 경로를 따른다.
